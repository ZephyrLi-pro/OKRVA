## 背景 (Context)

KylinBot 的记忆栈现有三个 backend：`QdrantMemory`（远程 HTTP）、`SqliteMemory`（本地 SQL + 应用层余弦相似度）、`PostgresMemory`（feature gated）。它们都通过 `crates/kylinbot-api/src/memory_traits.rs::Memory` trait 暴露统一接口，并在 `crates/kylinbot-memory/src/lib.rs` 的工厂里按配置字符串路由——路由经由 `crates/kylinbot-memory/src/backend.rs::classify_memory_backend` 把字符串映射到 `MemoryBackendKind` 枚举，然后 `create_memory_with_storage_and_routes`（对 `Qdrant` / `Postgres` 早 return）与 `create_memory_with_builders`（对 `Sqlite` / `Lucid` / `Markdown` / `None` / `Unknown` match）分别处理具体后端。Embedding 提供方同样通过工厂选择，其中 `kart-embedding` 已经把 `libkysdk-coreai-embedding` 接入到位（参考 commits b91b313 / f8a48ef / 937c8e1），SDK 缺失时降级到 `embeddings::NoopEmbedding`（`crates/kylinbot-memory/src/embeddings.rs:26`）。本变更把同样的 SDK 接入模板复用到向量库 `libkysdk-vector-engine-client`。

**SDK 形态**（由 `/home/pangyi-v11/cc-workspace/demo-for-vectorDB/main.cpp` 验证）：

```
VectorDataEngine* engine = vector_data_engine_create();
vector_data_engine_connect(engine, "<conn-id>");         // 不是 URL，是嵌入式实例 id
vector_data_engine_load_db_file(engine, "/path.db", false, NULL);
vector_data_engine_create_collection(engine, schema);
vector_data_engine_create_index(engine, coll, field, idx, type, metric);
vector_data_engine_insert(engine, coll, field_data[], n, &rows);
vector_data_engine_search(engine, args, timeout, &results);
vector_data_engine_hybrid_search_rrf(engine, coll, args[], n, ranker, top_k,
                                     output_fields[], m, timeout, &results);
vector_data_engine_query(engine, args, timeout, &results);
vector_data_engine_delete(engine, coll, expr, &rows);
vector_data_engine_destroy(&engine);
```

DataType 常量（demo 中的 magic number）：`INT64=5, VARCHAR=21, FLOAT_VECTOR=101, SPARSE_VECTOR=104`；FunctionType：`BM25=1`。所有 `create_*` 都返回不透明指针，配对的 `destroy_*` 必须显式调用，否则泄漏；`search/query` 的结果通过"二级指针 + 长度输出参数"返回，调用方负责按字段类型 free。

**约束条件**：

- 工作站和 CI 不能假设 `libkysdk-vector-engine-client-dev` 已安装 —— 必须像 `kart-embedding-sys` 一样在运行时 `libloading::Library::new` 加载，并提供 `stub` feature 用于纯编译验证。
- 不引入 `unsafe` 到 `kart-vector-database-sys` 以外的任何 crate（与现有 `aardvark-sys` / `kart-embedding-sys` 一致）。
- `Memory` trait 的方法签名保持不变（已有 Qdrant/SQLite/Postgres 三个 impl，签名稳定）。
- 配置兼容：新增字段必须有默认值，旧配置仍可加载。

## 目标 (Goals)

- 把 `libkysdk-vector-engine-client` 作为新的 `Memory` 后端 `KylinVectorDBMemory` 接入，与现有后端**平级**（不引入新 trait 层）。
- Hybrid 检索由 SDK 内置的 BM25 `FunctionSchema` + `hybrid_search_rrf` + `RRFRanker` 完成，**不复用** `vector.rs::hybrid_merge`（该路径目前仅 `SqliteMemory::sqlite.rs:680` 调用；Qdrant 路径未启用 hybrid_merge）。
- 在没有装 SDK 的机器上工作空间仍能 `cargo build` 与 `cargo test` 通过（stub feature）。
- 接入变更可按 4 个独立 commit 分次合入：sys crate → workspace 注册 → memory backend → 工厂 + 配置路由。

`ensure_collection()` 的 schema：

```
collection = self.collection
fields:
  f_id          INT64        primary_key=true, auto_id=true
  f_key         VARCHAR(128)
  f_content     VARCHAR(8192)
  f_category    VARCHAR(64)
  f_timestamp   VARCHAR(32)
  f_session_id  VARCHAR(64)
  f_embedding   FLOAT_VECTOR dimension = i32::try_from(embedder.dimensions())?
  f_sparse      SPARSE_VECTOR
functions:
  BM25(name="content_bm25", in=f_content, out=f_sparse)
indexes:
  (f_embedding, vector_index,        IndexType::IvfFlat,  MetricType::Ip)
  (f_sparse,    sparse_vector_index, IndexType 1201,      MetricType 201)
```

> **类型 ID 注释**：`IndexType` 1201 / `MetricType` 201 是 demo 中针对 SPARSE_VECTOR 的 magic number；sys crate 通过具名枚举包装这些常量，magic number 不外泄。具体命名以 SDK 头文件为准（实现时核对 `vectordataengine.h`），但本设计承诺：**应用层不再出现裸数字**。
>
> **维度类型转换**：`FieldSchema::dimension(d: i32)` 与 `EmbeddingProvider::dimensions() -> usize` 之间需要显式 cast。实现 MUST 用 `i32::try_from(dim)` 失败时返回 `KylinVectorDBError::InvalidInput`，不允许静默截断。
>
> **零维度边界**：若 `embedder.dimensions() == 0`（即注入的是 `NoopEmbedding`），`ensure_collection()` MUST 以 WARN 日志报告向量检索不可用并跳过 collection 创建；后续 `store/recall` 不崩溃、返回空（与 `QdrantMemory` 在 noop embedder 下的行为一致）。

`Memory::store()`：embed `content` → 列式 insert（`f_key, f_content, f_category, f_timestamp, f_session_id, f_embedding`，`f_sparse` 由 SDK 的 BM25 函数自动产出，`f_id` 由 auto_id 产出）。

`Memory::recall(query, limit, session_id, since, until)`（签名按 `crates/kylinbot-api/src/memory_traits.rs:128` 实际声明——不存在 `category_filter` 参数，请勿照搬旧文档）：

```rust
let q_vec = embedder.embed(query).await?;
let mut anns = vec![
    AnnSearchRequest::dense("f_embedding", limit as i32, &q_vec),
    AnnSearchRequest::sparse_text("f_sparse", limit as i32, query),
];
let ranker = RrfRanker::new(60);
let results = engine.hybrid_search_rrf(
    &collection, anns, ranker, limit as i32,
    &["f_key", "f_content", "f_category", "f_timestamp", "f_session_id"],
)?;
// 在 Rust 侧按 session_id 与 since/until 时间窗过滤（也可放进 SDK expression，
// 但 hybrid_search_rrf 的 expression 支持待 SDK 文档确认；初版在 Rust 侧做）
```

`Memory::get(key)`：`QueryArguments` 带 `expression = format!("f_key == \"{key}\"")`；返回首行。
`Memory::forget(key)`：`engine.delete(&coll, &format!("f_key == \"{key}\""))`。
`Memory::list(category, session_id)`（签名按 `memory_traits.rs:141`——参数是 `category` 与 `session_id`，**没有 `limit` 参数**）：`QueryArguments` 带 expression 按 category 与 session_id 拼，output fields 完整。
`Memory::count()`：用 `query` + `f_id > 0` 取所有 id 的长度（或如果 SDK 提供 count，用之；初版用前者）。
`Memory::health_check()`：`is_available() && engine.load_state(coll).is_ok()`。

### 2.1 专有接口（inherent methods on `KylinVectorDBMemory`）

`Database.h` 暴露的若干能力在 `Memory` trait 上没有对应方法（管理 / 内省 / 表达式批删 / upsert）。把它们以 inherent method 形式加在 `KylinVectorDBMemory` 上，与 trait 表面隔离；调用方在持有具体类型时可访问，trait object 视图不变。原则：

- **Memory trait 已覆盖** 的能力（`Insert/Search/HybridSearch/Query-by-pk/Query-by-expr-list/Delete-by-single-pk/GetLoadState/LoadDBFile/Connect/Disconnect/CreateCollection/CreateIndex`）**不**重复暴露，避免双入口。
- **trait 未覆盖** 的能力（collection lifecycle、schema 内省、`Upsert`、按表达式批删）以 inherent method 形式新增。
- **部分覆盖** 的能力（`Upsert`、按表达式批删）按反向委托：先实现 inherent 原语，再让 `Memory::forget` / `purge_namespace` / `purge_session` 内部委托过来。`Memory::store` 不改语义。

```rust
#[cfg(feature = "vectordb")]
impl KylinVectorDBMemory {
    // —— collection 管理 ——
    pub async fn has_collection(&self) -> anyhow::Result<bool>;
    /// 仅用于测试 / 重置 / 迁移；普通运行路径不该调用。
    pub async fn drop_collection(&self) -> anyhow::Result<()>;
    /// 一个 .db 文件可能承载多个 collection；返回当前 .db 全部 collection。
    pub async fn show_collections(&self) -> anyhow::Result<Vec<String>>;

    // —— 内省 ——
    pub async fn describe_collection(&self) -> anyhow::Result<CollectionDesc>;
    pub async fn describe_index(&self, field: &str) -> anyhow::Result<IndexDesc>;
    /// 比 `Memory::count()` 更全：含 row_count、index 状态等。
    pub async fn collection_statistics(&self) -> anyhow::Result<CollectionStat>;
    pub async fn drop_index(&self, field: &str) -> anyhow::Result<()>;

    // —— DML 扩展（trait 未覆盖；trait 方法反向委托过来）——
    /// Upsert：embed → 先 forget(key) 再 store；保持 Memory trait 不变。
    pub async fn upsert(
        &self,
        key: &str,
        content: &str,
        category: MemoryCategory,
        session_id: Option<&str>,
    ) -> anyhow::Result<()>;
    /// 按 SDK 表达式批删，返回删除行数。
    /// `Memory::forget` 实现为 `delete_by_expression(&format!("f_key == \"{key}\""))`,
    /// `purge_namespace(ns)` 实现为按 namespace 字段表达式批删。
    pub async fn delete_by_expression(&self, expr: &str) -> anyhow::Result<usize>;
}
```

`CollectionDesc / IndexDesc / CollectionStat` 在 `kart-vector-database-sys` 内定义为安全包装结构体（不外泄 SDK 裸指针），字段集合对齐 `types/CollectionDesc.h` / `types/IndexDesc.h` / `types/CollectionStat.h`。如 SDK 头文件中字段过多，sys crate 仅 mirror KylinBot 实际使用的子集（collection name / 字段列表 / 索引名 + 类型 + metric / row_count），其余在后续迭代加。

`Database::Upsert` 在 SDK 层是单次 RPC，比 `forget + store` 多一次往返；但端侧嵌入式无网络成本，且 BM25 FunctionSchema 在 insert 时自动重算 sparse 列，分两步语义无副作用。如果未来 profiling 显示是热点，再下沉为单次 SDK 调用。

**Step 2**：在 `crates/kylinbot-memory/src/lib.rs::create_memory_with_storage_and_routes` 加 early-return 分支（与现有 `Qdrant` 分支同形）：

```rust
if matches!(backend_kind, MemoryBackendKind::Vectordb) {
    #[cfg(feature = "vectordb")] {
        if !kart_vector_database_sys::is_available() {
            tracing::warn!("vectordb backend selected but SDK not found; \
                            falling back to NoneMemory");
            return Ok(Box::new(NoneMemory::new()));
        }
        let embedder: Arc<dyn embeddings::EmbeddingProvider> =
            Arc::from(embeddings::create_embedding_provider(
                &resolved_embedding.provider,
                resolved_embedding.api_key.as_deref(),
                &resolved_embedding.model,
                resolved_embedding.dimensions,
            ));
        match KylinVectorDBMemory::new_lazy(
            workspace_dir,
            &config.vectordb.db_name,
            &config.vectordb.collection,
            embedder,
        ) {
            Ok(m) => return Ok(Box::new(m)),
            Err(e) => {
                tracing::error!("KylinVectorDBMemory init failed: {e}; falling back to NoneMemory");
                return Ok(Box::new(NoneMemory::new()));
            }
        }
    }
    #[cfg(not(feature = "vectordb"))] {
        tracing::warn!("vectordb backend requested but feature disabled; falling back to NoneMemory");
        return Ok(Box::new(NoneMemory::new()));
    }
}
```

**Step 3**：在 `create_memory_with_builders` 的 `match` 中加 `Vectordb` arm（这条 builder-only 路径在 migration 等场景被调用，必须显式 cover，否则会落入 `Unknown → MarkdownMemory` fallback）：

```rust
MemoryBackendKind::Vectordb => {
    // builder 入口缺少 config + embedder，不能在这里真正构造 KylinVectorDBMemory。
    // 与 Postgres arm 一致，bail 让调用方走 storage_and_routes 入口。
    anyhow::bail!(
        "vectordb backend requires MemoryConfig + embedder; \
         call create_memory_with_storage_and_routes instead of create_memory_with_builders"
    )
}
```

**Step 4**：降级语义与 `kart-embedding` 在 SDK 缺失时降级为 `embeddings::NoopEmbedding`（`crates/kylinbot-memory/src/embeddings.rs:26`）的策略对称——注意两边的"noop"命名不同：memory 侧降级目标是 `NoneMemory`（`crates/kylinbot-memory/src/none.rs:9`，`Memory::name()` 返回 `"none"`），embedding 侧才叫 `NoopEmbedding`。**不要在工厂里写 `NoopMemory`，这个类型在仓库中不存在。**

## 关键决策 (Key Decisions)

| 决策                                 | 选择                              | 替代方案                          | 理由 |
|--------------------------------------|----------------------------------|----------------------------------|-----|
| sys crate 名                         | `kart-vector-database-sys`       | `kart-vector-engine-sys`         | 与现有分支 `feat/kart-vector-database-sys` 一致；用户明示。 |
| sys crate `edition`                  | `edition = "2021"`                | `edition.workspace = true` (`"2024"`) | 与 `kart-embedding-sys`（`edition = "2021"`）保持一致，避免单独一个 sys crate 提前迁移到 2024 后受 unsafe FFI / bindgen 兼容性影响；如果未来 `kart-embedding-sys` 一起迁移，再一并改。 |
| 接入层抽象                            | 直接 impl `Memory` trait          | 抽 `VectorStore` 中间 trait      | 现有只两个向量库 impl（Qdrant + 新），不预设第三个，避免 over-engineer。 |
| Hybrid 检索                          | SDK 内置 `hybrid_search_rrf` + BM25 | 应用层 `hybrid_merge`            | SDK 既有能力直接用；省一次 round-trip 与一次手写归一化。 |
| `.db` 路径                           | 配置 `[memory.vectordb.db_name]` + workspace_dir 拼接 | 硬编码 `~/.local/share/...`     | 与 SQLite 后端 `workspace_dir/memory/{db_name}.db` 一致；同一 KylinBot 实例的所有持久化都落在同一个 workspace 下。 |
| stub feature                         | 加                                | 不加，仅 feature gate            | 与 `kart-embedding-sys` 对称；让 CI 在不装 SDK 的 runner 上也能编 sys crate。 |
| SDK 缺失时的行为                      | 降级为 `NoneMemory` + WARN log    | 直接 panic                       | 与 `embeddings::create_embedding_provider("kart-embedding", ...)` 在 SDK 缺失时降级到 `NoopEmbedding`（`crates/kylinbot-memory/src/embeddings.rs:246-260`）的策略对称——注意 memory 侧降级目标叫 `NoneMemory`，不是 `NoopMemory`（后者不存在）。 |
| auto_id 主键                          | 用 SDK auto_id（`f_id` INT64）+ 单独 `f_key` 业务键 | 直接用 `f_key` 作 pk | demo 验证 SDK 的 auto_id 路径可用；业务键不一定保证唯一长度，单独存更稳。 |
| BM25 函数挂在 collection 上            | 是                                | 应用层手工分词                    | SDK 的 FunctionSchema 在 insert 时自动写 sparse 列，零额外工程。 |

## 风险与权衡 (Risks & Tradeoffs)

| 风险                                              | 缓解措施 |
|---------------------------------------------------|---------|
| SDK 不透明指针的 RAII / 内存所有权易写错           | 所有 `*mut Foo` 在 sys crate 内部用 `Drop` 包装；公开 API 不暴露裸指针；`SearchResults` / `QueryResults` 在 Drop 时调对应的 `destroy_*`；嵌套字段（`char**`、`float**`）按 demo 的释放顺序在访问器内复制后立即 free。 |
| `vector_data_engine_*` 在并发调用下的线程安全未文档化 | `VectorDBEngine` 内部用 `Mutex<*mut>`，所有调用串行化；与 `KylinTextEmbedding::session` 同样的策略。如果未来 SDK 文档明确并发安全，可放宽到 `RwLock` 或裸指针。 |
| Magic number（DataType=5/21/101/104，IndexType=1201/201 等）来源是 demo 不是 SDK 头文件 | 实现时核对 `<vectordataengine.h>` 与 `<coreai/error.h>` 中的 enum 定义；sys crate 用具名 enum 包装；如果数值变化，只改 sys crate 一处。 |
| BM25 hybrid 在低质量短文本上召回不稳定             | 接入 `vector_weight` / `keyword_weight` 类调参不在本变更范围；初版用 RRF `k=60` 默认值；如果集成测试发现问题，作为 follow-up issue。 |
| Memory trait 的 `count()` 在向量库里没有原生 API   | 用 `query` + 全表扫描的 expression 实现；性能在记忆条数较大时下降。可接受 —— `count` 在 KylinBot 现有调用点不在热路径。 |
| 多个 KylinBot 实例同时打开同一 .db 文件             | SDK 未声明文件锁语义；配置文档说明 ".db 路径应每个进程独占"；不在 sys crate 强制加锁（与 SQLite 路径一致）。 |
| bindgen 在 CI runner 上需要 `libclang`              | stub feature 跳过 bindgen；CI 默认走 stub。需要真编译的 release/PR 流程显式开 `vectordb` feature 并装 `libclang` + `libkysdk-vector-engine-client-dev`。 |
| pkg-config 同时需要 `kysdk-ai-common`               | sys crate 的 `build.rs` 通过 `cargo:rustc-link-lib=dylib=` 显式声明依赖；如有传递符号需要，再补 `kysdk-ai-common` 链接行。实现时由 `cargo build -F vectordb` 的链接错误驱动。 |

## 实现顺序与 commit 切分 (Implementation Sequence)

```
commit 1  feat(kart-vector-database-sys): add FFI sys crate skeleton
          - 整个 crate 自包含（不引用工作空间任何 crate）
          - 含 stub feature 与不依赖 SDK 的单元测试
          - 不修改工作空间 Cargo.toml（commit 2 才做）
          - PR 可独立 review；如果 sys 层不对，回滚不影响 memory

commit 2  chore(workspace): register kart-vector-database-sys as workspace member
          - workspace Cargo.toml 一行加 path 成员
          - 仅机械步骤；与 commit 1 拆开是仓库现行约定

commit 3  feat(kylinbot-memory): add KylinVectorDBMemory backend
          - 新 src/vectordb.rs
          - Cargo.toml 新增 optional dep + feature vectordb
          - lib.rs pub mod vectordb
          - 不修改 backend.rs 的 MemoryBackendKind 与工厂（`create_memory_with_storage_and_routes` / `create_memory_with_builders`）
          - 此 commit 后 cargo build -F vectordb 应通过

commit 4  feat(kylinbot-memory,kylinbot-config): wire vectordb backend
          - kylinbot-config 新增 [memory.vectordb] schema
```
